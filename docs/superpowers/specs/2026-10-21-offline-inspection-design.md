# Offline inspection outbox design

Purpose: retain observations and photos during intermittent connectivity, show exactly what is local versus acknowledged by the server, and publish once without duplicate records. Human explicitly authorizes routine design choices; coordinator owns execution, customer data writes, release and native acceptance. Architectural feature, implemented inline without children.

## Alternatives and selected boundary
A local note export alone would retain capture but leave manual transcription. Blindly replaying existing POSTs risks duplicates after a lost acknowledgement. Select a small additive outbox plus one transactional batch endpoint with durable receipts. Preserve old APIs, authorization, roles, subscription checks, case/photo quotas, billing and conversion workflow.

Start only from an existing authorized draft inspection freshly loaded online. Capture new rooms and findings (including a finding in an existing room), up to five photos per new finding; never edit or delete existing server records offline. New protocols use the existing online creation workflow. No automatic case conversion, protocol completion, messages, notifications or background uploads. PDF remains the existing server PDF after acknowledged publication.

## Access and honest offline limits
The current authenticated workspace opens a local notebook only after existing GET inspection succeeds and current scope/account match. Once open, network may disappear while capture continues. IndexedDB preserves drafts/photos across reload; reopening requires the same account's fresh authorized read. No protected API/navigation cache or offline-auth substitute. Thus cold launch in airplane mode is not promised. Signout/account switch hides drafts; successful existing account deletion removes that owner's new local data only. Team scope includes organization ID as well as account/protocol, preventing transfer between workspaces. Entitlement loss blocks publication; existing source gate remains unchanged. Explicit local deletion confirms and never deletes a server record.

## Local data and state
Version1 archive per owner+organization+protocol: draft ID UUID, revision, authorized baseline snapshot, created/updated times, new rooms UUID/name<=120/condition ok|notice|defect/notes<=1200, findings UUID/title<=180/description<=3000/category<=80/severity minor|normal|urgent, room reference existing-or-local; photo UUID/name<=250/MIME JPEG|PNG|WebP/size/hash with actual Blob. Bound 20 rooms, 50 findings, 5 photos per finding, 3MiB per photo, 20MiB per draft, 10 drafts/50MiB per owner. Empty/invalid visible values cannot save. Reject schema/future/malformed/wrong-owner/foreign references/duplicate IDs/nonfinite time/revision. Preserve corrupt bytes and show blocked storage; no guessed migration or silent eviction.

Single IndexedDB transaction stores immutable archive and photo blobs together, with expected revision checked inside transaction; draft mutation publishes only after completion. Failed transaction keeps previous saved archive and the editor's unsaved values. A sealed queued batch has stable operation UUID and exact body/photo hashes. Ordinary save cannot unseal it; a dedicated expected-revision rebase requires exact cancelled:true evidence plus explicit review. Photo identities cannot be reused by a second draft in the same scope. Once any upload is attempted, it cannot be edited; retain bytes until exact receipt acknowledgement. Statuses local draft, queued, outcome unknown/retry, conflict, acknowledged. No false sent status from connectivity, fetch initiation or optimistic UI.

## Server batch and reconciliation
Add POST /api/inspections/:protocolId/offline-batches behind unchanged auth and privateProFeature. Reuse inspectionAccess; verify account and organization scope, draft status, payload bounds and photo content/size/hash. New receipt table keyed actor+operation UUID with protocol, payload hash and stable JSON result; FK actor/protocol cascades on deletion. Client cannot provide acting user, organization, created_by, quota override or resulting case ID.

Serialize each inspection batch using transaction and locked protocol; check existing actor operation receipt first after current access/entitlement. Exact matching retry returns prior result, even if protocol has since completed; altered body/protocol under same key fails409. With no receipt, compare deterministic baseline including protocol fields, rooms, findings and attachment counts, not only protocol.updated_at. Conflict409 writes nothing. Show old/current facts, retain local additions, require explicit review/confirmation of refreshed baseline. A read-only absent receipt alone never permits rebase: first POST an actor/protocol/operation/hash-bound cancellation under the same protocol lock. If already committed, return its actual receipt. Otherwise insert an immutable receipt-table cancellation tombstone (empty payload, result.cancelled=true). A delayed POST under that old key is permanently rejected. Only matching cancelled:true evidence unlocks local rebase and a later new key. Ambiguous network result must query receipt through the same authorized endpoint; lost cancellation acknowledgement keeps the local batch sealed until its tombstone is recovered.

Insert all new rooms/findings/attachments and receipt in one database transaction, with new IDs assigned by server and explicit local-ID mapping. Known multipart Content-Length must be <=22MiB before staging, after existing authentication/Pro gates; unknown streaming length is rejected411. Individual files <=3MiB and total metadata-bound photo bytes <=20MiB. Staged upload files removed on validation/known rollback/duplicate; committed file references retained. A thrown COMMIT acknowledgement triggers fresh authorized READ COMMITTED recovery under the same protocol lock. Durable receipt plus actual stored-file ownership resolves success/duplicate. If recovery remains unknown, retain possibly committed files; never infer rollback from transport failure. No endpoint calls case conversion or changes case/photo quota. Existing finding-to-case workflow remains explicit and server-guarded. No network/customer writes executed during implementation; use injected pure storage/transaction fixtures.

## Native shared UI and layout
Separate small React outbox component, model, IndexedDB repository, and API adapter; scoped entry inside InspectionDetail. Use stacked cards with explicit local/saved/queued/acknowledged labels and visible retry/conflict details. Unsaved textarea values retained after failures; browser unload warning for dirty drafts. Window-width CSS, min-width:0, wrapping, scrollable dialogs, sticky actions with env safe-area bottom, keyboard scroll and dynamic viewport sizing. Preserve WebView origin/navigation/file/security settings. Android uses same product UI. iOS host provenance remains coordinator task; no source-only native/Duo claim.

Server injectable transaction tests include failed staged files cleanup and atomic receipt/data commit.
